# HeatSense AI

**Urban Heat Mitigation & Cooling Decision Support System**
Project-I (BTCO16706) — Target city: Surat, Gujarat

> Cut the city into 100 m × 100 m cells, model seasonal Land Surface Temperature (LST) with XGBoost, explain drivers with TreeSHAP, and present planners with Pareto-optimal, budget-aware cooling interventions through a FastAPI + React dashboard.

## 1. Project Overview

| Layer | Technology |
|---|---|
| Grid | 100 m × 100 m analytical cells over Surat Municipal Corporation |
| Data Sources | Landsat 8/9 thermal, Sentinel-2 optical, SMC boundaries via Google Earth Engine |
| ML Model | XGBoost regressor, one per season (summer / monsoon / post-monsoon / winter) |
| Features | NDVI, albedo, LULC class, built-up fraction, road density, building height |
| Explainability | TreeSHAP per cell |
| Optimization | NSGA-II (pymoo) — minimise cost, maximise cooling, equity-aware |
| Backend | FastAPI · Pydantic v2 · JWT auth · PostgreSQL + PostGIS · GeoAlchemy2 |
| Frontend | React 19 · TypeScript · Vite · Leaflet · Recharts |

Full research notes, base papers, dataset links, and the phased build plan live in `plan.md`.

## 5. CUDA / GPU Setup

XGBoost, LightGBM, and CatBoost can all accelerate training on a CUDA-capable NVIDIA GPU. This section covers setting up CUDA from scratch.

### 5.1 Check if you have a compatible GPU

```powershell
# Windows
nvidia-smi
```

You need an NVIDIA GPU with Compute Capability ≥ 6.0 (GTX 10xx / RTX series or better). If `nvidia-smi` is not found, you either don't have an NVIDIA GPU or the drivers are not installed.

### 5.2 Install NVIDIA drivers (if needed)

Download and install the latest Game Ready or Studio driver from:
https://www.nvidia.com/Download/index.aspx

After install, confirm with `nvidia-smi`. Note the **CUDA Version** shown in the top-right corner (e.g. `12.6`) — this is the maximum CUDA version your driver supports.

### 5.3 Install CUDA Toolkit

1. Go to https://developer.nvidia.com/cuda-downloads
2. Select your OS / architecture / installer type
3. Download and run the installer (choose **Custom** and install only the CUDA Toolkit if you already have drivers)
4. After install, confirm:

```powershell
nvcc --version
# Should print: Cuda compilation tools, release 12.x
```

Also add CUDA to `PATH` if the installer did not (Windows):
```
C:\Program Files\NVIDIA GPU Computing Toolkit\CUDA\v12.x\bin
C:\Program Files\NVIDIA GPU Computing Toolkit\CUDA\v12.x\libnvvp
```

### 5.4 Install cuDNN (optional but recommended)

cuDNN is needed by some deep-learning libraries and speeds up certain CUDA ops.

1. Download cuDNN for your CUDA version from https://developer.nvidia.com/cudnn (requires free NVIDIA developer account)
2. Extract and copy `bin/`, `include/`, `lib/` into the CUDA Toolkit folder:
   ```
   C:\Program Files\NVIDIA GPU Computing Toolkit\CUDA\v12.x\
   ```

### 5.5 Verify CUDA with XGBoost

After activating your `.venv` and installing `requirements.txt`:

```python
python -c "
import xgboost as xgb, numpy as np
m = xgb.XGBRegressor(device='cuda', n_estimators=1)
m.fit(np.array([[0.],[1.]]), np.array([0.,1.]))
print('XGBoost CUDA OK')
"
```

### 5.6 GPU training flags per library

| Library | CPU flag | GPU flag |
|---|---|---|
| XGBoost | `device='cpu'` | `device='cuda'` |
| LightGBM | `device='cpu'` | `device='gpu'` |
| CatBoost | `task_type='CPU'` | `task_type='GPU'` |

The training script (`ml/src/models/train_xgboost.py`) auto-detects CUDA via `check_cuda_available()` when `--device auto` (default). Override with `--device cuda` or `--device cpu`.

### 5.7 LightGBM GPU build (optional)

The default `lightgbm` wheel is CPU-only. For the GPU build:

```bash
pip uninstall lightgbm -y
pip install lightgbm --install-option=--gpu
# or on newer pip:
pip install lightgbm[gpu]
```

> LightGBM GPU support requires the CUDA Toolkit and OpenCL. For most use cases the CPU build is fast enough.

### 5.8 CatBoost GPU

CatBoost's published wheel already includes CUDA support — no extra step needed beyond installing CUDA Toolkit ≥ 11.

## 6. Database Setup

### 6.1 Install PostgreSQL 16 + PostGIS 3.4

**Windows:**
1. Download from https://www.postgresql.org/download/windows/
2. Run installer; note the superuser (`postgres`) password you set
3. After install, open **Stack Builder** (bundled) → select your PostgreSQL 16 installation → **Spatial Extensions** → install PostGIS 3.4

**Linux (Ubuntu/Debian):**
```bash
sudo apt install postgresql-16 postgresql-16-postgis-3
```

**macOS (Homebrew):**
```bash
brew install postgresql@16 postgis
```

### 6.2 Create user, database, and enable PostGIS

```sql
-- Run in psql as the postgres superuser
psql -U postgres

CREATE USER heatsense WITH PASSWORD 'heatsense';
CREATE DATABASE heatsense OWNER heatsense;
\c heatsense
CREATE EXTENSION IF NOT EXISTS postgis;
CREATE EXTENSION IF NOT EXISTS postgis_topology;
\q
```

### 6.3 Apply schema

```bash
psql -U heatsense -d heatsense -f database/schema.sql
```

### 6.4 Initialize via the app (recommended)

```bash
cd backend
python -m app.db.init_db
```

This creates all tables and seeds the interventions catalogue.

## 8. ML Pipeline

Run these steps **in order**. Each script writes outputs that the next script reads.

### 8.0 Activate venv and set working directory

```bash
# from repo root
.venv\Scripts\activate   # Windows
# or
source .venv/bin/activate  # Linux/macOS

cd ml
```

### 8.1 Authenticate Google Earth Engine

```bash
earthengine authenticate
# Follow the browser prompt; credentials are saved to ~/.config/earthengine/
```

### 8.2 Export rasters from GEE

```bash
python src/data/gee_extraction.py
# Outputs → data/raw/gee_exports/
# NOTE: GEE exports run asynchronously; the script polls until done.
```

### 8.3 Build the 100 m grid

```bash
python src/data/grid_builder.py \
    --boundary data/raw/surat_boundary.geojson \
    --out data/processed/grid_cells.geojson
```

### 8.4 Assemble the feature table

```bash
python src/data/feature_engineering.py \
    --grid data/processed/grid_cells.geojson \
    --gee-dir data/raw/gee_exports \
    --buildings data/raw/open_buildings.geojson \
    --roads data/raw/osm_roads.geojson \
    --out data/processed/cell_features.parquet
```

### 8.5 Train models (XGBoost + LightGBM + CatBoost)

```bash
# Auto-detect GPU (uses CUDA if available, falls back to CPU):
python src/models/train_xgboost.py \
    --features data/processed/cell_features.parquet \
    --out-dir models_store

# Force GPU:
python src/models/train_xgboost.py \
    --features data/processed/cell_features.parquet \
    --out-dir models_store \
    --device cuda

# Force CPU:
python src/models/train_xgboost.py \
    --features data/processed/cell_features.parquet \
    --out-dir models_store \
    --device cpu
```

Outputs: `models_store/xgboost_<season>.json`, `models_store/metrics.json`

### 8.6 Compute SHAP values

```bash
python src/explainability/shap_analysis.py \
    --features data/processed/cell_features.parquet \
    --models-dir models_store
```

### 8.7 Compute feasibility caps

```bash
python src/data/feasibility_caps.py \
    --grid data/processed/grid_cells.geojson \
    --version-id 1
```

### 8.8 Precompute cooling coefficients (NSGA-II surrogate)

```bash
python src/optimization/cooling_coefficients.py \
    --features data/processed/cell_features.parquet \
    --models-dir models_store \
    --out models_store/cooling_coefficients.parquet
```

### Pipeline summary

```
GEE exports
  → grid_builder.py          → data/processed/grid_cells.geojson
  → feature_engineering.py   → data/processed/cell_features.parquet
  → train_xgboost.py         → models_store/xgboost_<season>.json
  → shap_analysis.py         → populates heat_predictions.shap_values in DB
  → feasibility_caps.py      → populates feasibility_caps in DB
  → cooling_coefficients.py  → models_store/cooling_coefficients.parquet
  → FastAPI + Frontend
```

## 14. Current Status: Production-Ready Platform

The HeatSense AI system is fully implemented, verified, and operational:

- **Complete Spatial Coverage**: 868 analytical 100m grid cells spanning the full 28.4 km × 27.2 km Surat Municipal limits (including Pandesara GIDC, Varachha, Katargam, Begampura, Sachin, Udhna, and Dumas Coastline).
- **Thermal Heatmap & Analytical Visualizer**: Continuous smooth thermal gradient rendering (using dynamically scaled Gaussian kernel blending) with Esri Satellite, OpenStreetMap, and Dark basemaps (100% free, no API keys needed).
- **Interactive Explanations**: Click or touch any cell across Surat to inspect surface metrics (Built-up, NDVI, Albedo, Road Density) and live TreeSHAP feature attributions.
- **Microclimate What-If Simulator**: Interactive intervention modeling (Cool Roofs, Tree Canopy, Permeable Pavements) with 10-year budget costing and physical land-use capacity caps.
- **NSGA-II Pareto Frontier**: Mathematical multi-objective optimization balancing budget (₹ Lakhs) against city-wide cooling (°C) and social equity.
- **Model Benchmarks & Deep Learning**: Rigorously evaluated XGBoost, Random Forest, ResNet-50 transfer learning, and NASA-IBM Prithvi-EO 2.0 foundation architectures using 5-fold spatial block cross-validation.
- **Executive Policy Brief & Data Export**: Integrated Surat Municipal Action Brief modal and JSON assessment export for urban planners and municipal authorities.
- **FastAPI Backend & Automated Test Suite**: Production API endpoints under `/api/v1` passing 100% of unit and integration test suites.
